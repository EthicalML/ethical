## [AI vs Human - Starcraft II Edition](https://deepmind.com/blog/alphastar-mastering-real-time-strategy-game-starcraft-ii/)

The [DeepMind team did it again](https://deepmind.com/blog/alphastar-mastering-real-time-strategy-game-starcraft-ii/), this time taking the challenge to the game of Starcraft II. DeepMind covered it [live in Youtube last Thursday](https://www.youtube.com/watch?v=cUTMhmVh1qs) (check the short video [here](https://www.youtube.com/watch?v=UuhECwm31dM)). [SPOLIER ALERT] In summary, DeepMind started by introducing the new AI called AlphaStar (a [recurrent-network+attention-like reinforcement learning model](http://inoryy.com/post/deepmind-starcraft2-next-big-thing-ai/)). DeepMind then brought in two top players known as "Mana" and "TLO" to discuss the 10 matches where AlphaStar beat them both. "Mana" then played a re-match live, which he won. It was a truly interesting game, primarily as Mana used a lot of the knowledge gathered from his previously lost games. The video is quite long, but there are a lot of interesting parts - one of the most interesting points were the [limitations that were introduced to AlphaStar](https://medium.com/@aleksipietikinen/an-analysis-on-how-deepminds-starcraft-2-ai-s-superhuman-speed-could-be-a-band-aid-fix-for-the-1702fb8344d6) to make sure games against humans were "fair". For anyone curious to learn more, the core DeepMind team [hosted an AMA in Reddit](https://www.reddit.com/r/MachineLearning/comments/ajgzoc/we_are_oriol_vinyals_and_david_silver_from/).

## [From zero to distributed](https://towardsdatascience.com/there-are-two-very-different-ways-to-deploy-ml-models-heres-both-ce2e97c7b9b1)

"If an ML model makes a prediction in Jupyter, is anyone around to hear it?". Great [short tutorial](https://towardsdatascience.com/there-are-two-very-different-ways-to-deploy-ml-models-heres-both-ce2e97c7b9b1) that covers the benefits of horizontally-scalable architectures over flask-wrapped-like model deployments This is a very good (super) small scale version of our [conversation last week](/newsletter/6/) introducing [Uber's Michaelangelo framework](https://towardsdatascience.com/doing-machine-learning-the-uber-way-five-lessons-from-the-first-three-years-of-michelangelo-da584a857cc2). This tutorial builds a queue-enabled machine learning serving system using MLQ for the queue interface, and the [tensorflow.js library](https://js.tensorflow.org/) to perform the inference on the front-end. Great stuff.

## [Tensorflow 2.0](https://medium.com/tensorflow/whats-coming-in-tensorflow-2-0-d3663832e9b8)

An exciting milestone for one of the most widely adopted libraries in deep learning. In [this great post released](https://medium.com/tensorflow/whats-coming-in-tensorflow-2-0-d3663832e9b8) by the core team, they cover some of the high level objectives. The main point they mention is that Tensorflow 2.0 will see all the components that have been build separately brought in together as a comprehensible unified platform. This includes all its flavours, such as Tensorflow Serving, Tensorflow Lite, Keras, tensorflow JS and beyond. [In this blog post](http://inoryy.com/post/tensorflow2-deep-reinforcement-learning/), Iorni showcases key Tensorflow 2.0 (experimental) features by building a deep reinforcement model.

## [Monitoring Parking with R-CNN](https://medium.com/@ageitgey/snagging-parking-spaces-with-mask-r-cnn-and-python-955f2231c400)

Adam Geitgey proposes to [automate manual annoying tasks](https://medium.com/@ageitgey/snagging-parking-spaces-with-mask-r-cnn-and-python-955f2231c400) with deep learning. In his article he walks us through on how he built an R-CNN to monitor for parking spaces so he can get notified when one is free. Great insight on how image ML tasks are often tackled by using domain knowledge to modularising the problem into multiple "layers" (e.g Detect spaces -> detect cars -> detect parking spaces that are newly empty).

## MLOps = [Featured OS Libraries](https://github.com/EthicalML/awesome-machine-learning-operations)

This week's edition is focused on AutoML and Neural Architecture Search frameworks which fall on our [Responsible ML Principle #4](https://ethical.institute/principles.html#commitment-4). The four featured libraries this week from the [Awesome MLOps list](https://github.com/EthicalML/awesome-machine-learning-operations) are

- [Autokeras](https://github.com/jhfjhfj1/autokeras) - AutoML library for Keras based on "[Auto-Keras: Efficient Neural Architecture Search with Network Morphism](https://arxiv.org/abs/1806.10282)".
- [ENAS-PyTorch](https://github.com/carpedm20/ENAS-pytorch) - Efficient Neural Architecture Search (ENAS) in PyTorch based on [this paper](https://arxiv.org/abs/1802.03268).
- [Neural Architecture Search with Controller RNN](https://github.com/titu1994/neural-architecture-search) - Basic implementation of Controller RNN from [Neural Architecture Search with Reinforcement Learning](https://arxiv.org/abs/1611.01578) and [Learning Transferable Architectures for Scalable Image Recognition](https://arxiv.org/abs/1707.07012).
- [Neural Network Intelligence](https://github.com/Microsoft/nni) - NNI (Neural Network Intelligence) is a toolkit to help users run automated machine learning (AutoML) experiments.

If you know of any libraries that are not in the ["Awesome MLOps"](https://github.com/EthicalML/awesome-machine-learning-operations) list, please do give us a heads up or feel free to [add a pull request](https://github.com/EthicalML/awesome-machine-learning-operations)!
